# 从会运行到能解释这个 Agent

这是持续迭代的个人项目。我们共同讨论设计和实验；AI 负责实现、测试、调试与文档，
你负责理解关键决策、配置本机密钥、运行实验并提出改进。无需一次读懂所有代码。

## 第一步：理解一次正常的机器学习实验

先运行 README 的离线 demo，打开生成的 `report.md`、`summary.json` 和 `splits.json`。

需要能解释：训练集用于什么？为什么不能根据测试集挑模型？为什么准确率高不一定意味着
少数类预测得好？为什么预测时也必须使用训练时拟合的缺失值处理与类别编码？

代码阅读顺序：`config.py` → `data.py` → `models.py` → `worker.py`。
小实验：把预测文件的特征列顺序打乱，预测应该不变；删掉一列，应该得到明确报错。

## 第二步：理解自主实验闭环

阅读 `runner.py`、`search.py`、`llm.py`。V1 不执行模型生成的 Python；它校验 JSON，
然后从共享候选空间中执行一个方案。执行器定义怎么评分，LLM 决定下一步尝试什么。

需要能解释：什么信息反馈给 Agent？为什么同一个方案不能只换解释就重复运行？
为什么把代码执行、计费和评分留给固定程序？离线 mock 与真实 LLM 的区别是什么？

小实验：运行一次 baseline，再运行 random，比较验证集选择过程和最终测试结果。
配置 DeepSeek 后，再看模型给出的实验假设是否真的引用了已有证据。

Windows 使用 `python -m tabular_lab auth login` 首次保存密钥，以后自动读取。
`credentials.get_api_key()` 先读环境变量，再读 Windows 凭据管理器；`llm.JSONClient.ask()`
只在调用 API 时读取密钥。配置密钥属于宿主运行环境，不属于 Agent 的实验决策。
训练容器没有凭据存储或密钥环境变量的挂载。

## 第三步：理解预算、失败与复现

查看 `events.jsonl` 中的 `llm_request`、`llm_response`、`experiment_result`。
计费使用实际返回的 token，用量未知不当成免费。价格与汇率是记录在运行中的配置快照。

小实验：把预算设为 0，运行应该停止新的 LLM 调用并保留基线；不给 API key 时，
不能把结果当成完成的 LLM 实验。用 replay 重放已记录的决策，观察它不产生新 API 成本。

固定方案、数据和 CPU 环境能较好复现；重新调用 LLM 不保证同样的决策；GPU 也可能有数值差异。
复现时先核对 manifest，而不是只看一个 seed。

## 第四步：判断 Agent 是否有效

正式表格任务使用 Wine Quality 和 Adult，sklearn 小数据主要用于快速回归测试。
比较固定基线、随机搜索、LLM Agent；后两者必须使用相同候选空间与资源上限。
观察三个种子的均值、标准差、失败率、耗时和费用。

如果 Agent 没超过随机搜索，也是一条有效结论。下一步应检查候选空间、反馈信息和
决策质量，而不是换一次随机种子只报告最好成绩。基准数据上的多次开发会削弱“未见任务”结论。

## 第五步：V2 自动编程

安装 Docker Desktop 并启用 Linux engine 后，再构建 worker 镜像。
阅读 `sandbox.py` 和 `docker/worker.py`：模型代码能看到什么？验证标签放在哪里？
为什么生成的 joblib 只能在容器内加载？为什么杀死 Docker CLI 后还要删除容器？

V2 先使用 CPU 容器；5070 的本机 GPU 训练属于 V1 的 CatBoost 路径，两者无需一起配置。
通过真实容器集成测试后，才能把 V2 标为本机验证通过。
